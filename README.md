# grilling

> 把你的想法连环拷问到可以拍板。

一个 Agent Skill（智能体技能）。它不急着给答案，而是先把你脑子里那个还没成形的想法**问透**——一轮只问"此刻就能回答"的问题，直到没有任何一处是被默默假设掉的。

适用于 Claude Code、WorkBuddy，以及任何支持 Agent Skills 规范（`SKILL.md` + YAML frontmatter）的客户端。

---

## 它解决什么问题

大多数"帮我做个方案"的对话，死于同一个地方：**题目本身没定义清楚就开干了。**

"我想做个爆款视频""这个产品要做得高级一点""帮我规划一个课程"——

这些话里没有一个词是可判定的。AI 顺着往下做，做出来的东西自然也对不上你脑子里的那个画面。等到成品出来才发现方向错了，前面的活儿全白干。

grilling 强制在动手之前停下来，用苏格拉底三问 + 设计树，把你的想法一层层拆到**每条分支都有明确决定**为止。

## 安装

### 方式一：一键脚本（推荐）

**macOS / Linux**

```bash
git clone https://github.com/<你的用户名>/grilling.git
cd grilling
bash install.sh
```

**Windows（PowerShell）**

```powershell
git clone https://github.com/<你的用户名>/grilling.git
cd grilling
powershell -ExecutionPolicy Bypass -File install.ps1
```

脚本会自动检测你机器上已有的 skills 目录（`~/.claude/skills`、`~/.workbuddy/skills`），把 skill 复制进去。重复运行即更新，可放心执行。

### 方式二：手动安装

把 `skills/grilling/` 整个目录复制到你的 skills 目录下，确保最终路径是：

| 客户端 | 安装路径 |
| --- | --- |
| Claude Code | `~/.claude/skills/grilling/SKILL.md` |
| WorkBuddy | `~/.workbuddy/skills/grilling/SKILL.md` |

其他客户端：放进它约定的 skills 目录即可，目录名保持 `grilling`。

装完**重启会话**，skill 才会被加载。

### 卸载

删掉那个 `grilling` 目录就行，没有任何残留依赖。

## 怎么用

直接说人话触发，不需要记命令：

- "拷问我一下" ／ "grill me"
- "帮我把这个想法问透"
- "压力测试我的方案"
- "先别做，先问我"

也可以在你抛出一个计划、选题、脚本之后补一句"先追问我几轮"。

## 它长什么样（示例节选）

你说：*「我想做一个教人用 AI 的抖音号，目标是涨粉。」*

```
🔪 S1 定义 · 我先重述：你真正想解决的不是"做 AI 号"，而是"在 3 个月内
拿到一批会持续看你内容的人"。涨粉只是手段。对吗？
➡️ "持续看你内容"——你要的是关注数，还是完播率和主页访问？

🔪 S2 假设：这件事成立的前提是——AI 工具教程的观众还没有被你熟悉的那几个
头部账号吃掉。如果这个假设不成立，你做的每一条都是在跟 50 万粉的号抢同一批人。
➡️ 最脆弱的一环：你有没有一个"他们会看、但大号不会讲"的切口？

🔪 S3 反面：最想否定你的人会说——"又一个念文档的 AI 教程号，你的内容
和官方文档有什么区别？"
➡️ 这句话你现在能答上来吗？
```

你答完之后，它才开始建树、进入第一轮真正的问题。

## 它是怎么工作的

**设计树 + frontier**：把你的想法当成一棵决策树，每个决定都分叉出子决定。**frontier（前沿）**是"前置条件都已解决、此刻就能问"的那批问题。每轮把整个 frontier 一次问完，不挤牙膏；答案依赖本轮其他问题的，推到下一轮。frontier 清空 = 结束。

**开场三问**：建树之前先确认定义、找出最脆弱的假设、替你站到对立面。定义不过关就不往下走。

**六条铁律**，其中三条最容易被 AI 违反：

- 找事实是它的活儿，不是你的——能查的自己查，只把**决策**丢给你。
- 每个问题必须带推荐答案，而且推荐答案要先自己找一遍反例。
- 不主动动手。在你确认共识之前，它不写方案、不开始执行。

**会问 vs 不会问**：范围、取舍、优先级、边界——这些能问。而"封面用红还是蓝""开头节奏快一点还是慢一点"这类**看不到实物就判断不了**的问题，它会立刻停下，改成给你一个最便宜的验证方式（做个样张、写两版开头），而不是在原地反复追问。这是防止对话失控的关键。

**结束交付共识**，且强制区分三类信息：已验证的事实 / 当前的假设 / 确实未知。并指出**唯一一个**关键变量——它一变，一半以上的决定要推倒重来。

---

## 什么时候别用它

- 你只想要结论、不想要被提问（代码审查、直接给建议）。
- 问题已经非常具体，没有决策空间了。
- 你要的是"做出来看看"的效果判断——这类问题它本来就会拒答并让你先出样张。
